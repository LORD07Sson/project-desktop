# API

Эндпоинты сервера (`miniapp/server.py` в репозитории бота), которые
вызывает клиент из `src/app/*.js`. Добавляя новый вызов, допишите его сюда.

## Базовый URL и авторизация

- `API_BASE` в `src/app/api.js`
- Все запросы (кроме `/desktop/pair`) несут заголовок
  `X-Init-Data: dsk_<токен>` — desktop-токен, полученный при входе по коду
  (см. [README](../README.md#вход)). Сервер отличает его от
  Telegram initData по префиксу `dsk_` (`_validate_desktop_token` в
  `miniapp/server.py`)
- Токен хранится в нативном хранилище учётных данных ОС
  (`src-tauri/src/token_store.rs`), не в localStorage/файле

## Вход

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| POST | `/desktop/pair` | `{code, label}` | `{token, telegram_id, name}` — код из `/desktop` в боте, одноразовый, 5 минут |
| GET | `/whoami` | — | `{telegram_id, is_admin}` — используется при восстановлении сессии, чтобы проверить, что токен ещё не отозван. Имени тут нет: для шапки клиент отдельно дёргает `/me` (см. `hydrateIdentity` в `src/app/auth.js`) |

Любой ответ `401`/`403` на запрос с токеном клиент трактует как
«сессию отозвали»: чистит токен из хранилища ОС и возвращает на экран
входа (`session-expired` в `src/app/api.js`). Исключение — сам
`/desktop/pair`, где `401` значит просто «неверный код».

## Обзор и профиль

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/overview` | Сводка по команде: счётчики отчётов по статусам, просрочка, топ-5 исполнителей, доступ, тикеты, дни рождения — вкладка «Обзор» |
| GET | `/trend` | Динамика за 14 дней (создано/завершено по дням) — график на «Обзоре» |
| GET | `/overview/monthly-top` | Топ-5 за последние 30 дней по закрытым отчётам — «Рейтинг месяца» |
| GET | `/me` | Личный профиль: статистика (assigned/overdue/completed_*), донат по активным отчётам, `role_breakdown`, `team`, `badges`, `studio_rank: {place, total}` — вкладка «Я» |
| POST | `/me/profile` | `{status_text, bio}` — правка своего статуса/о себе |
| GET | `/me/activity` | Личная лента последних действий по отчётам |
| POST | `/presence/ping` | Хартбит «я сейчас в приложении» — раз в минуту, влияет на `is_online`/`online` у команды и профиля |

## Карточка отчёта — чек-лист, заметки, файлы

| Метод | Путь | Тело | Назначение |
|---|---|---|---|
| GET | `/report/{public_id}/checklist` | — | Список пунктов чек-листа |
| POST | `/report/{public_id}/checklist` | `{text}` | Добавить пункт |
| POST | `/report/{public_id}/checklist/{item_id}/toggle` | — | Отметить/снять пункт |
| POST | `/report/{public_id}/checklist/{item_id}/delete` | — | Удалить пункт |
| GET | `/report/{public_id}/notes` | — | Список заметок |
| POST | `/report/{public_id}/notes` | `{text}` | Добавить заметку |

Время на дорожке у заметки хранится префиксом в самом тексте —
`[4:12] шум на вдохе` — отдельного поля под него в API нет. Десктоп
разбирает префикс регуляркой (`parseNoteTime` в `src/app/utils.js`) и
показывает отдельной меткой; боту и мини-аппу это просто первые символы
строки, так что ничего не ломается. Если когда-нибудь появится
настоящее поле — клиент переедет на него, а старые заметки останутся
читаемыми.
| GET | `/report/{public_id}/files` | — | Файлы отчёта (для карточки) |
| POST | `/report/{public_id}/files/{file_id}/qc` | — | Серверная AI-проверка звука (Silero VAD — точнее локальной эвристики клиента) |
| GET | `/report/{public_id}/files/{file_id}/download` | — | Скачать файл. Запрос делает Rust (`download_report_file` в `main.rs`) с обычным заголовком `X-Init-Data`, путь сохранения выбирает нативный диалог. Раньше это была ссылка `<a target="_blank">` с `init_data` в query — она и не работала (webview не открывает новых окон), и уносила токен в URL |

## Игры (`/api/games/*`)

Код — `miniapp/games_api.py` на сервере, база — `games_data/games.db`. Заголовок `X-Init-Data`, как везде.

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET/POST | `/me` | страна цен, привязанные Steam-аккаунты |
| GET | `/search`, `/specials`, `/free`, `/sales` | поиск, скидки (с оценкой и числом отзывов), бесплатные раздачи, ближайшие распродажи (даты ориентировочные) |
| GET | `/app/{id}` | карточка: цена, история, `at_lowest`, метки (ранний доступ, семейный доступ, карточки, DLC, языки) |
| GET | `/app/{id}/extra`, `/news`, `/achievements`, `/regions`, `/charts` | ProtonDB и Steam Deck, новости, достижения, цены по странам, онлайн |
| GET/POST/DELETE | `/wishlist` | желаемое; цель — цена (`target`) и/или скидка (`target_discount`) |
| GET/POST | `/wishlist/export`, `/wishlist/import` | резервная копия списка |
| GET | `/alerts?unseen=1`, POST `/alerts/seen` | уведомления о цене для десктопа |
| GET | `/profile`, `/library`, `/launch/{id}` | профиль Steam, библиотека, адрес запуска |
| GET | `/suggest?q=` | подсказки названий по полному списку игр Steam (`IStoreService/GetAppList`, обновляется раз в сутки) |
| GET | `/app/{id}/stats`, `/app/{id}/news?kind=patch` | личная статистика игры (`GetUserStatsForGame`), патчноуты (`tags=patchnotes`) |
| GET | `/friends`, `/profile/lookup?q=` | друзья с открытым списком (кто во что играет), публичный профиль по ссылке, имени или SteamID64 |
| GET/POST | `/wishlist`, `/wishlist/sync` | желаемое подтягивается из Steam само (`IWishlistService/GetWishlist`): при открытии вкладки и раз в 30 минут. Убранная у нас игра не возвращается, пока её не добавят снова; при отвязке Steam пришедшие оттуда игры убираются |
| GET | `/library?family=1` | библиотека с семейным доступом (`include_family_licenses`), часы на Steam Deck и Linux |
| GET | `/deals?min=&maxprice=&minpct=&sort=&tag=&q=&start=&limit=` | весь каталог скидок Steam (около 5 700 игр: сервер собирает его из `IStoreQueryService/Query` по 1000 за запрос и обновляет раз в 10 минут). Сортировка: `discount`, `price`, `price_desc`, `reviews`, `popular`, `name`; страницы по 48 |
| GET | `/releases/calendar?from=&to=`, `/releases?from=&to=&q=&only=&kind=` | календарь релизов как у SteamDB: по дням до пяти самых ожидаемых игр (клетка их листает), пометки «в желаемом»/«в библиотеке», блок «без точного дня» по месяцам; и список за период с рейтингом и онлайном у вышедших. Сервер проходит весь список «скоро выйдут» (~60 000 игр) и первые 5000 вышедших, берёт игры с точной датой на ~13 месяцев и вышедшие за 21 день, помечает взрослые игры (дескрипторы 3 и 4) и показывает их только при `adult=1`; `pers=1` ставит выше игры по вашим жанрам (самые сыгранные игры библиотеки); индекс собирается за ~1,5 минуты в фоне, кэш 40 минут |
| GET | `/store/home`, `/store/calendar`, `/store/foryou`, `/browse` | витрина как в Steam: карусель со скриншотами и отзывами, страницы скидок, личный календарь выходов на 3 недели (желаемое первым, затем по вашим жанрам; `adult=1` включает 18+), подборка по вашим жанрам, каталог по жанру |
| GET | `/app/{id}/reviews`, `/tags` | итог и тексты отзывов (`appreviews`), жанры (`IStoreService/GetTagList`) |
| GET | `/status` | когда последний раз проверялись цены и делалась копия базы |

Онлайн всех игр из топа и из желаемого записывается каждые 5 минут, у игры, карточку которой сейчас открыли, — каждые 2.
Сервер раз в 30 минут обновляет цены желаемого и сравнивает с целью. Уведомление
уходит один раз при переходе «не выполнено → выполнено»: цель достигнута, исторический
минимум или начало скидки. Сообщение идёт в Telegram и копится для `/alerts`. По понедельникам
после 12:00 (МСК) приходит дайджест со скидками из желаемого, раз в сутки делается копия базы
(`games_data/backups`, хранятся 7).

## Не через сервер бота

- **Обновления** — Velopack (`HttpSource` в `src-tauri/src/main.rs`),
  по прямым ссылкам на файлы релизов GitHub, без токена и API (репозиторий публичный,
  свой прокси не нужен). Старый прокси `/api/desktop/update` на
  сервере бота удалён (был мёртвым кодом после перехода на Velopack)
- **Канал обновлений** — стабильный (по умолчанию, `build.yml`, только
  на изменение `VERSION`) или альфа (`build-alpha.yml`, на каждый push
  в `main`, версия `VERSION-alpha.<номер запуска>`) — переключается в
  Настройках (`get_update_channel`/`set_update_channel` в `main.rs`,
  хранится через `tauri-plugin-store`). Каналы независимы — у каждого
  свой `releases.{channel}.json`, стабильный клиент альфа-сборки не видит
- **QC звука по локальному файлу** — вообще не ходит на сервер, целиком
  в Rust (`src-tauri/src/audio_qc.rs`), вызывается через
  `invoke("qc_analyze", {path})`
