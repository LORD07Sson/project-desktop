# Project Desktop (старая версия, PySide6)

Кроссплатформенный (Windows / Linux / macOS) десктоп-клиент студии
поверх того же API, что и мини-апп в Telegram (`miniapp/server.py`) —
один и тот же код, PySide6 сам отвечает за нативный вид на любой из
трёх ОС. Готово: вход по коду из бота, список отчётов с фильтрами и
сортировкой, смена статуса (одиночная и массовая), массовое назначение
исполнителя, локальный QC звука, трей с уведомлениями о новых
назначениях и просрочках.

## Системные требования

- Python 3.11+
- **ffmpeg** в PATH — нужен только для QC звука (`ffmpeg -version` должен
  работать в терминале); Windows/macOS — https://ffmpeg.org/download.html,
  Linux — из пакетного менеджера (`apt install ffmpeg`, `dnf install ffmpeg`, ...)

## Запуск (для разработки/проверки)

```
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
python app.py
```

## Как войти

1. Напишите боту в Telegram: `/desktop`
2. Бот пришлёт одноразовый 6-значный код (действует 5 минут)
3. Введите код в открывшемся окне приложения

Токен сохраняется в родном хранилище учётных данных ОС (через
`keyring`: Credential Manager на Windows, Keychain на macOS, Secret
Service/KWallet на Linux) — при следующем запуске входить заново не
нужно, пока токен не отозван.

## Устройство

- `config.py` — адрес сервера (`API_BASE`)
- `auth.py` — хранение токена (keyring, с фолбэком на файл в `%APPDATA%\Project`
  на Windows / `~/.config/Project` на Linux/macOS)
- `api.py` — HTTP-клиент, тонкая обёртка над теми же ручками, что дёргает мини-апп
- `login_dialog.py` — окно входа по коду
- `main_window.py` — список отчётов: поиск/фильтры по статусу и приоритету,
  сортировка по клику на заголовок, двойной клик — сменить статус одному
  отчёту, выделение нескольких строк (Ctrl/Shift) открывает панель
  массовых операций (смена статуса, назначение исполнителя)
- `audio_qc.py` — сам анализ (клиппинг/шум/долгие паузы), целиком на ffmpeg+numpy,
  без похода на сервер; та же логика и пороги, что у серверного `audio_qc.py` бота,
  но без Silero VAD (лишняя зависимость для десктоп-сборки) — паузы ищем порогом
  громкости, как в запасном пути у серверной версии
- `qc_dialog.py` — окно QC: выбор файла, анализ в фоновом потоке (`QThread`), список находок
- `tray.py` — значок в трее, опрос новых назначений/просрочек раз в минуту (`assignee=me`
  на сервере уже умеет разворачивать "me" в вызывающего), уведомление только о том, что
  появилось НОВОГО с прошлого опроса — не спамит на каждом цикле одним и тем же
- `app.py` — точка входа; крестик у главного окна сворачивает в трей (опрос продолжает
  идти в фоне), по-настоящему выйти — «Выйти» в окне или «Выход» в меню трея

## Готовые сборки

`releases/linux/project-desktop` — собран и проверен локально
(запускается, доходит до окна входа без ошибок).

Windows и macOS кросс-компилировать из Linux нельзя (PyInstaller
собирает только под ту ОС, на которой запущен) — поэтому их собирает
CI: `.github/workflows/build.yml` на каждый push в `main` гоняет
сборку на настоящих windows-latest/macos-latest/ubuntu-latest раннерах
GitHub Actions и **автоматически публикует релиз** на странице Releases
репозитория с готовыми файлами: `project-desktop-windows.exe`,
`project-desktop-linux`, `project-desktop-macos.app.tar.gz` —
проще всего скачивать оттуда. Версия релиза берётся из файла `VERSION`
(сейчас `0.1.0`) — при каждом push релиз с этим тегом пересоздаётся
заново с новой сборкой; чтобы выпустить следующую версию, поднимите
число в `VERSION`.

Собрать вручную на самой той ОС тоже можно — три команды в
`releases/windows/BUILD_HERE.md` / `releases/macos/BUILD_HERE.md`.
