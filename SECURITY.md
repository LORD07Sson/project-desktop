# Политика безопасности

## Область

Репозиторий публичный, но клиент используется только внутри студии
PROJECT и ходит в закрытый сервер студии — сторонним пользователям
самого приложения не завести. Ниже — как безопасно сообщить о проблеме
и что вообще относится к поверхности атаки этого клиента.

## Как сообщить об уязвимости

Публично (issue, комментарий) — не сообщайте. Напишите напрямую
владельцу репозитория (LORD07Sson) или ответственному за бота в студии
с описанием:

- что нашли и как воспроизвести;
- версию клиента (`Настройки` → видно внизу, либо файл `VERSION`);
- ОС и способ установки (готовый релиз / сборка из исходников).

Ответ и статус — в течение нескольких дней, срок закрытия зависит от
серьёзности.

## Что считается уязвимостью в этом проекте

- Обход входа по коду (`/api/desktop/pair`) без знания кода из бота
- Возможность прочитать/подделать токен `dsk_...` другого пользователя
- Инъекция через поля отчёта/заметок, которая выполняется в WebView
  клиента (XSS) — фронтенд рендерит данные с сервера напрямую в DOM,
  см. `src/app/utils.js`, функция `esc()` — если где-то экранирование
  пропущено, это баг безопасности
- Подмена обновления (см. «Автообновление» ниже)
- Утечка токена из нативного хранилища ОС (`keyring`) в лог/файл/сеть

Не относится к уязвимостям: сама доступность бизнес-функций
администратору студии (модель доверия — все, кто получил код через
`/desktop` в боте, уже являются членами команды).

## Автообновление: что гарантируется сейчас

Обновления собирает и публикует Velopack (`vpk pack`/`vpk upload` в
`.github/workflows/build.yml`), клиент читает их через `GithubSource`
(см. `src-tauri/src/main.rs`). Это значит:

- пакеты **не подписаны** ни ключом Velopack, ни сертификатом
  Authenticode — единственная гарантия целостности сегодня это HTTPS до
  GitHub и права на публикацию релизов в этом репозитории;
- секретов `TAURI_SIGNING_PRIVATE_KEY*` в CI больше нет: они относились
  к `tauri-plugin-updater`, от которого проект ушёл. Если они ещё
  заведены в настройках репозитория — их стоит удалить;
- поэтому компрометация аккаунта с правами на релизы = компрометация
  всех установленных клиентов. Подпись пакетов — известный незакрытый
  пункт, а не «и так защищено».

## Обработка секретов в этом репозитории
- Токен десктоп-клиента (`dsk_...`) хранится на диске пользователя
  только в нативном хранилище учётных данных ОС (Credential Manager /
  Keychain / Secret Service), не в открытом файле — см.
  `src-tauri/src/token_store.rs`
- Сервер хранит не сам токен, а его SHA-256-хеш (`database.py`,
  `create_desktop_token`/`resolve_desktop_token`) — компрометация базы
  не раскрывает действующие токены напрямую
- Известное ограничение: картинки (аватары, баннеры, постеры через
  `img_proxy`) грузятся тегом `<img>`, которому не приделать заголовок,
  поэтому токен там уходит в query-строку и попадает в access-логи
  сервера. Место ровно одно — `mediaUrl()` в `src/app/api.js`;
  правильное решение — короткоживущий одноразовый ключ для медиа на
  стороне сервера. Всё остальное (включая скачивание вложений отчёта)
  ходит с токеном в заголовке `X-Init-Data`
- Файл, перетащенный в окно, читает Rust-команда `upload_report_file`, и
  читает она только те пути, которые пользователь сам перетащил (см.
  `DroppedFiles` в `src-tauri/src/main.rs`) — чтобы XSS в WebView не
  превращался в «прочитать любой файл на диске»

## Старый Python-клиент

`legacy_python_client/` — архив, не собирается и не поддерживается. В
нём есть фолбэк хранения токена в открытый файл `session.json`, если
`keyring` недоступен; на текущий Tauri-клиент это не распространяется
(там только нативное хранилище, без фолбэка).
